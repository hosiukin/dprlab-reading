# Phase 2d — LLM 读取与 QC 策略总纲

BRAF n316 项目（316 例、2,204 次调用、evidence 命中 73–88%）沉淀的读取策略。
用户自己的字段设计优先，本篇提供经过验证的"怎么做稳"的通用规则。

## 1. 生成参数（写死，不开放给模型自由发挥）

| 参数 | 值 | 理由 |
|---|---|---|
| temperature | **0** | 结构化抽取要确定性 |
| enable_thinking | **false**（`chat_template_kwargs`） | Qwen3.x 不关思考会混入正文/耗尽 max_tokens 出空回复 |
| max_tokens | 1500/次（思考模型 3000+） | 防 runaway |
| 输出格式 | **只输出 JSON**，提示词第一行就声明 | 解析失败率显著下降 |
| patient_sn | **不出现在 prompt 文本里** | 只用于结果对齐，防 ID 泄进模型输出 |

## 2. 长文本分块（不截断！）

- 历史 run 曾做"8000 字截断/关键词压缩"，结果 21% 病史丢文本、关键事件漏抽——**禁止截断**。
- 滑窗切块：**4500 字窗口 + 250 字重叠**；块数公式与切块函数严格一致（不产生碎尾块）。
- 每块 prompt 带**跨块续读说明**：块序号 `第 {chunk_idx}/{n_chunks} 块`、上一块尾部 200 字
  （`{tail}`）；规则里写明"与上块重复的事件照常输出，合并层去重；事件被截断时标记
  `continues_next_chunk`"。
- 去重放在 **merge 层**做（按键去重），别指望模型自己判断"这块是不是重复"。

## 3. 锚点 → 窗口两步法（时间字段的防漂移策略）

研究问题涉及"某个时间窗内的事件"时，不要一步到位，分两轮：

1. **第一轮只抽锚点**（如"首次转移后第一次全身治疗的 start_date"）——任务小、口径单一、
   准确率高；产出锚点表人工抽检。
2. **第二轮用锚点定义窗口**（start_date → progression_date），只抽窗内事件。
   窗口定义写在提示词里（"仅抽取 X 日期之后、Y 之前的事件"）。

BRAF n316 的对应实现：DGX 侧 32/33（锚点）→ 34/35（窗口）；新管线 step1（全部治疗行）→
治疗窗对齐影像。一步法的问题：模型对"首次/转移后/同一方案"这类限定词的口径会漂移，
拆成两步后每步口径都能人工校验。

## 4. 证据锚定（evidence anchoring，本项目最重要的规则）

**每条抽取结果必须带 `evidence_verbatim`：从原文逐字复制的支撑句（≤120 字），不得改写、
不得拼接两处。**

- merge 层做**回文校验**：把 evidence 与原文都去掉全部空白后做子串匹配（取前 80 字比对），
  命中 → `evidence_hit=true`。空白不敏感是为了容忍排版差异；截 80 字是为了防超长"证据"蒙混。
- `evidence_hit` 率是**核心 QC 指标**：BRAF n316 新管线 73–88%（旧 run 曾低到 34%，就是
  没有强制逐字）。低于 ~70% 说明提示词或模型有问题，先修再放量。
- 未命中的行**不删除**，标记后进入人工复核清单——其中既有模型幻觉，也有"改写了日期格式"
  这类可修复情况。

## 5. 领域词表与幻觉防御

- 建**标准化词表**（lexicon）：标准名 + 正则别名（商品名、英文、**错别字**）。BRAF n316 的
  药典含 8 个靶向药，特意收录了"维莫菲尼/维罗非尼/西妥西单抗"等真实出现过的错拼——
  医生打字错误是漏抽的主因之一。
- 词表注入提示词（`{lexicon}` 占位符），要求模型把原值归一到标准名。
- **组合判定不信任模型**：如"双靶组合"（EGFR+BRAF/MEK 同方案句）由 merge 层用词表
  复算（`dual_combo_lexicon`），模型的 `is_dual_target_candidate` 只当参考。
- **幻觉剔除**：模型给的标准化药名必须能在方案原文或证据句里验证，验证不到的剔除。
- 缩写要显式展开（如 BRAF n316 的 `VIC` = 维莫非尼+伊立替康+西妥昔单抗）。

## 6. 执行 vs 建议（假阳性主源）

提示词写硬规则：只有"行/给予/予/口服/应用/化疗N程/C1"等**执行表述**才抽；
"建议/拟/可考虑/准备/计划/咨询/介绍临床研究/因费用未换"一律不抽。
merge 层再按 `intent` 字段过滤一次（双保险）。BRAF n316 曾因此产生 3 例双靶假阳性，
加规则后消除。

## 7. 日期规范化

- 统一 `YYYY-MM-DD`；只有年月 → `YYYY-MM`；只有年 → `YYYY`；无日期 → 空串。
- 中文日期（2023年5月8日）、点分（2023.5.8）、斜杠（2023/5/8）全部归一。
- **宁缺勿编**：没有就空，模型不得推断日期。

## 8. 响应解析（宽容而有序）

1. strip → 去掉 ```json 围栏 → 取首个 `{` 到末个 `}` 的片段；
2. 修尾逗号（LLM 常见畸形）；
3. `json.loads` 失败 → `json_repair` 兜底（可选依赖）；
4. 仍失败 → 记 warning、计入未完成，checkpoint 重跑自动补。

## 9. 运行工程（断点续跑 + 并发 + 重试）

- **checkpoint 键**：`(step, patient_sn, chunk_idx)`；响应 append 到 jsonl，重启时已成功键
  跳过，失败/空回复/损坏行自动重跑。
- 重试：连接类错误退避重试（10/20/30s）；4xx（除 429）不重试（改配置才有用）。
- 并发 `--workers 8`（spark 服务端 max-num-seqs 8，再高只是排队）。
- Windows 多线程写文件必须加锁（append 交错会产生损坏行——真实踩坑）。

## 10. QC 与人工裁决（不可跳过的收尾）

每次 run 后必产出 QC 报告，至少含：

- 各表行数（抽取条数）、去重前后对比；
- `evidence_verbatim` 覆盖率与**回文命中率**；
- 机器标记的患者数（如双靶候选）；
- 明确的"机器标记≠结论"声明。

**机器判定只做候选**：BRAF n316 全量 run 标记双靶 117 人，最终名单必须人工逐条核对
evidence（联合 vs 序贯、执行 vs 建议、癌种导向）后才可进分析。人工裁决工作表 = 
`patient_sn | 机器标记 | evidence_verbatim | 原文上下文 | 人工结论`。

## 11. 放量前流程

1. `--limit 20` 小样本试跑（或挑 5–10 例覆盖长短文本）；
2. 人工核对 evidence_hit 与字段质量，改提示词/词表；
3. `estimate` 核对调用量与 token 预算（经验：中文 0.6–1.0 token/字 + 每调用 ~1000 token 模板开销）；
4. 全量跑（可 `--steps` 只跑需要的步骤省一半量）；
5. merge → QC 报告 → 人工裁决清单。
