# Phase 2b/2c — 数据清洗、患者 ID 体系与多文本整理

目标：把医院导出的原始表格变成"一个患者一行、文本可用、ID 可溯源"的提取输入。
以下策略全部来自 BRAF n316 项目（316 例转移性结直肠癌）的实际做法，按用户数据情况裁剪。

## 先摸底（不要跳过）

对每张表确认：

1. **表是什么**：病史/出院记录、病理报告、影像检查（CT/MRI/超声）、检验、随访表？
2. **ID 字段有哪些**：患者级 ID（patient_sn/病历号）？住院号（inpatient_no）？门诊号（outpatient_no）？
   检查号/标本号？同一患者在表里出现多少次？
3. **文本字段**：整段病史？所见+结论分开？多列自由文本？
4. **日期字段**：格式是否统一（`2023-05-06 14:49:02` / `2023年5月` / `2023.5.6`）？
5. **编码与表头**：UTF-8 还是 GBK？第一行是不是表头？

## 表格清洗清单

医院导出表的常见坑（BRAF n316 全部踩过）：

| 问题 | 处置 | pandas |
|---|---|---|
| GBK/GB18030 编码 | 读入时显式指定 | `pd.read_csv(f, encoding="gbk")` |
| 错位表头（前几行是横幅/中文名/英文名） | 先 `head()` 看前 5 行再定 header | BRAF 检查表：横幅 1 行 + 中文表头 + 英文表头 → `header=2` |
| 同一检查/记录重复导出 | 按"业务键"去重，别按行号 | 见下文各类文本的去重键 |
| 全半角/首尾空格/换行不一致 | 规范化后再比对 | `str.replace(r"\s+","")` 只用于**比对**，原文保留 |
| 日期混杂格式 | 统一解析成 `YYYY-MM-DD`，解析失败单独标记（不要静默丢弃） | `pd.to_datetime(..., errors="coerce")` + 统计失败率 |
| 一表多义（同一列混存"执行"与"建议"） | 提取阶段处理，清洗阶段不动文本内容 | 见 methodology.md |

**原则：清洗只做结构修复（编码/表头/去重/日期），不改写临床文本内容**——文本是提取的
唯一证据源，改一字就少一分证据锚定的可靠性。

## 患者 ID 体系（核心）

**`patient_sn` 是唯一标识符**；住院号/门诊号是溯源键，**一律保留、绝不丢弃**。

推荐产出一张映射表（ID map），所有下游表都通过它对齐：

```text
patient_sn | inpatient_no_id | outpatient_no_id | 来源表 | 备注
SYNTH0001  | 0000674896      | —                | 检查表  |
```

- **跨表对齐**：任何新表先算 `patient_sn ↔ 住院号` 的对应关系，发现同一 patient_sn 对应
  多个住院号是正常现象（多次住院），同一住院号对应多个 patient_sn 则是数据问题，必须先查。
- **BRAF n316 实例**：影像检查表同时带 `patient_sn`（哈希型患者 ID）与
  `HSK-病史-all_inpatient_no_id`（住院号）两列——patient_sn 用于全部主键与合并，
  住院号保留在映射表里用于回查原始病历系统。
- 若源数据只有住院号没有患者级 ID：先按住院号归并出"患者"（同一生日+性别+姓名哈希等），
  生成自己的 patient_sn，再建映射。**不要直接拿住院号当 patient_sn**（一次住院一个号，
  会把同一患者拆成多人）。
- ID 全部当**字符串**处理（`astype(str)`），防止 `0000674896` 被读成数字丢前导零。

## 同一患者的多次文本资料整理

### 病史/出院记录（多文档）

一个患者多次住院 → 多份文书。三种策略，按研究问题选：

1. **选择单一文书**（BRAF n316 的做法）：整段病程信息最全的那份（常是**末次或最长**的
   conclusion）。必须留审计字段：`selected_note_n`（选了第几份）、`last_note_len`、
   `longest_rank_from_last`、`middle_longest_len` 等，让人工可复查"为什么选这份"。
2. **按时间序拼接**：适合事件分散在多次住院的场景。拼接时插入分隔标记
   （`【第N次住院 YYYY-MM-DD】`），给模型时间锚点。
3. **逐份抽取再合并**：文书很长或研究问题按住院划分时；抽取结果在 merge 层按
   (patient_sn, 事件键) 去重。

### 病理报告

- 通常一份报告一个标本：组织 `(patient_sn, 标本号/报告日期)`；文本常含"免疫组化/基因检测"段。
- BRAF n316 的做法：单独一轮提取任务专抽病理/分子特征（如 BRAF 状态），与病史提取的
  结果在患者级合并，而不是混在病史任务里。
- 注意病理报告的"印象/结论"与"描述"要分开抽，防止把"待查/建议加做"当成结论。

### 多次影像学检查

一个患者几十次检查是常态。BRAF n316 的整理方式（`examples/reading_pipeline_2026-08-31/imaging_prepare.py`
为可运行范例）：

1. **过滤模态**：只要 CT/MRI（或研究需要的模态）；
2. **合并文本**：`影像所见(exam_finding) + 影像结论(exam_conclusion)` → `exam_text`
   （加"影像所见：/影像结论："前缀，模型区分更稳）；
3. **去重键**：`(patient_sn, exam_date_day, exam_type, exam_text_sha1)` ——文本内容哈希进键，
   同日同类型的重复导出一键识别；
4. **按患者+日期排序**，得到每人一条"影像时间线"；
5. **对齐治疗时间窗**（研究"治疗期间影像"时）：每条检查算
   `days_from_first_systemic`（距首次全身治疗天数）和窗内标记
   （`in_dual_window` = open/closed/before/after + `days_from_dual_start`）。
   治疗窗结束日期缺失时先标 `open`，待治疗方案提取全量跑完后重跑即得 `closed` 精确窗；
6. **覆盖度审计**：每人检查次数、首末检查日期、窗内条数（`patient_exam_coverage`），
   评估"谁的影像证据够回答研究问题"。

## 产出物标准

进入读取阶段（methodology.md）前，应得到：

- `reading_df.csv`：`patient_sn` + `conclusion`（或等价文本列），一人一行（或一人多行+分块策略）；
- `id_map.csv`：patient_sn ↔ 住院号/门诊号 映射；
- 影像线（若需要）：`imaging_exam_organized.csv` + 覆盖度表；
- 每张产出表附简单 manifest（行数、来源文件、生成日期），保证可复算。
